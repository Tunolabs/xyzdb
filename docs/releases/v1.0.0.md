# v1.0.0 — 1.0 launch: BUSL-1.1, secure by default

**Branch**: `main` · **Type**: major — **on-disk format break** (a 0.8.x data directory is refused at open; recreate from source — see [Compatibility](#compatibility)) · **Tag**: `v1.0.0` (2026-07-30).

> **Read this first — two behaviour changes break existing deployments.**
> Upgrading in place requires acting on both:
>
> 1. **Default bind moved `0.0.0.0` → `127.0.0.1`.** A non-loopback bind without
>    `--auth-token` is now refused at startup with a non-zero exit. *Migration:*
>    set `--auth-token` (recommended), or pass `--insecure-allow-no-auth`
>    explicitly for a trusted network. The container image still commands
>    `0.0.0.0`, so a plain `docker run` without a token fails safe rather than
>    exposing an open server.
> 2. **`STATS`, `SHOW STATS` and `/metrics` now require the token when one is
>    set.** This breaks any Prometheus scrape already pointed at the engine.
>    *Migration:* add an `Authorization: Bearer <token>` credential to the
>    `scrape_config`. `/health` and `/ready` stay on the unauthenticated
>    allowlist.
>
> There is also an on-disk format break versus 0.8.x — see
> [Compatibility](#compatibility) before pointing 1.0 at existing data.

## TL;DR

1. **Business Source License 1.1 + a specified wire protocol.** The repository
   ships under BUSL-1.1 with `LICENSE`, `NOTICE`, `TRADEMARKS.md`, and
   `PERMISSIONS.md`; the wire protocol is now specified in `PROTOCOL.md` and may
   be implemented freely by anyone.
2. **Secure by default.** The server binds loopback and refuses an open
   non-loopback bind without a token; `STATS`/`SHOW STATS`/`/metrics` follow the
   token. (Both are the breaking changes above.)
3. **`xyzdb-mcp --connect` authenticates** against a token-protected server.
4. **Vectors are discoverable** — the searchable vector field surfaces in
   `SHOW PROFILE` and as a top-level field in the MCP `describe_lobe` tool.
5. **`NEAREST` degrades instead of failing** when the latency budget expires
   mid-hydration — a prefix-correct partial, never a failed legitimate answer.
6. **`Value` decode is depth-capped** — a deeply nested payload can no longer
   exhaust the decode stack.
7. **On-disk format moved** (24-byte spatial key); a pre-1.0 data directory is
   recreated from source, not migrated in place.
8. **Apache-2.0 client packages ship with 1.0** — `xyzdb` on crates.io, PyPI,
   and npm; the installable clients, published from a separate repository under
   Apache-2.0, so an application can depend on a client without the BUSL-1.1
   engine license.

## Licensing and protocol surface

xyzDB 1.0 is published under the **Business Source License 1.1** (Change Date
**2029-08-01**, Change License Apache-2.0). The package is `LICENSE`, `NOTICE`,
`TRADEMARKS.md`, and `PERMISSIONS.md`; `docs/license-change-dates.md` records the
per-version Change Date and `.ci/license-version-parity.sh` keeps the version and
date aligned across `LICENSE`, the workspace manifest, that table, and `NOTICE`.
The whole repository — including the reference client under `examples/` — is
BUSL-1.1; the installable client packages (`xyzdb` on crates.io, PyPI, and npm)
are Apache-2.0 and ship from a separate repository.

The **wire protocol is specified in `PROTOCOL.md`**: the request framing (V1–V4),
the bearer-token preamble, the response envelope, the 16 MiB frame cap, and the
HTTP surface multiplexed onto the same TCP port. It is written from the
implementation so third parties can build compatible clients, and it may be
implemented freely, by anyone, under any license (see `NOTICE`).

## Secure by default

Two networking defaults changed so a fresh deployment is not accidentally open
(both are called out in _Read this first_ above, with migration steps):

- **Loopback bind by default.** `xyzdb-server` binds `127.0.0.1`. A non-loopback
  bind without `--auth-token` is refused with a non-zero exit; `--insecure-allow-no-auth`
  overrides it for a trusted network.
- **Introspection follows the token.** `STATS`, `SHOW STATS`, and `/metrics`
  return the engine stats snapshot, so with `--auth-token` set they now require
  authentication. Only the `/health` and `/ready` liveness probes stay
  unauthenticated.

## Vector discoverability

A lobe's searchable vector field is now first-class in introspection. `SHOW
PROFILE` carries a `Vector:` line naming the field, and the MCP `describe_lobe`
tool surfaces it as a top-level `vector` object (`field` plus `dim`, the vector
length), distinct from a `null` when the lobe declares no searchable field. A
client can discover what a lobe can answer a `NEAREST` over without guessing.

## MCP `--connect` authentication

`xyzdb-mcp --connect` now reads `XYZDB_TOKEN` and sends the bearer-token preamble,
so it works against a server started with `--auth-token` instead of failing the
handshake.

## NEAREST budget: degrade, not fail

A highly selective residual filter (fewer than `k` rows pass) forces `NEAREST` to
descend the whole gravity bucket in score order; when that crossed the wall-clock
budget the query previously returned an error. It now returns the highest-scoring
passers found within budget as `PaginatedRecords { has_more: true, cursor: None }`
— a prefix-correct partial. The budget stays a latency wall, never a recall wall;
the unbounded scoring scan still fails fast. See `docs/xytalk-spec.md` §2.20.

## Value decode depth cap

`Value` is the type every stored datum is made of, and it nests through `List`
and `Map`. Its decoder now caps nesting depth, so a deeply nested payload — even
one inside the 16 MiB frame — is rejected with a typed error instead of
exhausting the decode stack. Decoding of valid data is unchanged; only
pathologically deep nesting is refused.

## Compatibility

- **On-disk format break versus 0.8.x — a pre-1.0 data directory is refused at
  open.** The spatial key widened from 22 to 24 bytes to reserve a 2-byte
  satellite (sub-gravity) axis; the axis is always `0` today so behaviour is
  identical to the old layout, but the byte offsets moved, so keys written by an
  earlier build are not decodable by 1.0 (`MANIFEST_VERSION` is now `5`). The
  engine rejects an older data directory at open with a clear message.
- **Migration path:** there is no in-place migration tool for this jump —
  **recreate the dataset from source** against 1.0. (Record blobs themselves —
  V1/V2/V5 — still decode unchanged; the break is the spatial-key/manifest
  layout, which gates the whole directory.)
- **Client wire protocol is unchanged** (V1–V4, now specified in `PROTOCOL.md`);
  existing clients that do not present a token still work against a loopback or
  `--insecure-allow-no-auth` server, subject to the two behaviour changes above.
